34  Tables in APA 7 style

Tables are the other half of how findings are communicated. Where figures show patterns, tables show numbers precisely. A well-designed table lets the reader extract specific values that a figure would only approximate. Two kinds of tables dominate empirical psychology: descriptive statistics tables (means, SDs, sample sizes, correlations) and model results tables (coefficients, standard errors, p-values, effect sizes). This chapter shows how to build both correctly, in conformance with the American Psychological Association’s Publication Manual, 7th edition (APA, 2020), and how to produce them efficiently in R. It also notes that doing tables in Word or in a similar word processor is perfectly acceptable and that the principles transfer regardless of the tool.

34.1 APA 7 principles for tables

The 7th edition of the APA Publication Manual (American Psychological Association, 2020, §§7.8-7.21) sets out specific requirements for tables in psychology manuscripts. The principles are worth knowing whether or not you publish in APA-format journals, because they reflect long-standing conventions about what makes a table readable.

The essential requirements are:

  • Numbered with an Arabic numeral above the table (Table 1, Table 2, …).
  • A descriptive title in italics on the line below the table number, indicating what is in the table without abbreviation.
  • Column headings that label each column clearly. Spanner headings group related columns under a common label.
  • A note below the table explaining any non-obvious abbreviations, the meaning of asterisks, the sample size, and the source of the data if it is not the manuscript’s own.
  • Minimal lines. APA tables use only horizontal lines: one above the column headings, one below them, and one at the bottom of the table. No vertical lines. No internal horizontal lines between rows (except spanner separators).
  • Numbers right-aligned and decimal-aligned within columns. Text left-aligned.
  • Consistent decimal precision within a column. Choose two or three decimals as appropriate and use the same number throughout.

The spirit of these rules is that the table should be readable at a glance, the units and meaning of every number unambiguous, and nothing decorative or distracting included.

34.2 Descriptive statistics tables

The most common table in a psychology paper is the descriptive table: variable name, mean, SD, sample size, perhaps a couple of additional statistics. We will build one for vgames_study.

vgames <- read.csv("data/vgames_study.csv")

The simplest table is a summary by condition.

The basic R object prints OK but is not in publishable form. For a polished APA-style table, use the gt package, which gives fine-grained control over titles, formatting, alignment, and footnotes.

if (requireNamespace("gt", quietly = TRUE)) {
  library(gt)
  desc_table |>
    gt() |>
    tab_header(
      title    = md("**Table 1**"),
      subtitle = md("*Descriptive statistics by experimental condition*")
    ) |>
    cols_align(align = "left", columns = "Condition") |>
    cols_align(align = "right", columns = -1) |>
    fmt_number(columns = -c(1, 2), decimals = 2) |>
    tab_source_note(
      source_note = md("*Note*. *N* = 120 participants. Aggression scored 1-10; trait hostility and empathy scored 1-7. *M* = mean; *SD* = standard deviation.")
    )
} else {
  desc_table
}

The gt package’s output is publishable as-is, both as HTML in a rendered book and as an image or LaTeX in a manuscript. The same code produces tables formatted correctly for journal submission with minimal further work.

A second pattern useful for descriptive tables is a correlation matrix. The psych::corr.test() function produces a complete matrix with significance markers; gt formats it.

cor_matrix <- vgames |>
  select(aggression, trait_hostility, empathy, hours_weekly) |>
  cor() |>
  round(2)

cor_df <- as.data.frame(cor_matrix)
cor_df$Variable <- rownames(cor_df)
cor_df <- cor_df[, c("Variable", "aggression", "trait_hostility",
                     "empathy", "hours_weekly")]

if (requireNamespace("gt", quietly = TRUE)) {
  library(gt)
  cor_df |>
    gt() |>
    tab_header(
      title    = md("**Table 2**"),
      subtitle = md("*Correlation matrix of key study variables*")
    ) |>
    fmt_number(columns = -1, decimals = 2) |>
    cols_label(
      Variable        = "Variable",
      aggression      = "1",
      trait_hostility = "2",
      empathy         = "3",
      hours_weekly    = "4"
    ) |>
    tab_source_note(
      source_note = md("*Note*. *N* = 120. Numbers in column headings correspond to the variable in the corresponding row.")
    )
} else {
  cor_df
}

The standard APA convention is to number the rows (and use those numbers as the column headings), so the table is symmetric and the reader can quickly find any specific correlation. Pearson r values are typically reported to two decimal places, without the leading zero (e.g., .45 rather than 0.45), and significance markers (*, **, ***) are added in the footnote.

34.3 Model results tables

The other standard table is the regression output. R’s default summary(lm(...)) is the right starting point but not the right format for a paper. The modelsummary package produces a publication-ready version with one function call.

fit1 <- lm(aggression ~ condition, data = vgames)
fit2 <- lm(aggression ~ condition + trait_hostility, data = vgames)
fit3 <- lm(aggression ~ condition * trait_hostility, data = vgames)

if (requireNamespace("modelsummary", quietly = TRUE)) {
  library(modelsummary)
  modelsummary(
    list("Model 1" = fit1,
         "Model 2" = fit2,
         "Model 3" = fit3),
    stars  = TRUE,
    output = "gt",
    fmt    = 3,
    coef_rename = c(
      "conditionviolent"                  = "Condition (violent)",
      "trait_hostility"                   = "Trait hostility",
      "conditionviolent:trait_hostility"  = "Condition x Hostility"
    ),
    notes  = "*Note*. Standard errors in parentheses. *p* < .05 (*), *p* < .01 (**), *p* < .001 (***)."
  )
} else {
  cat("(modelsummary not installed; on your machine the table would show\n")
  cat("the three nested models side by side with coefficients, SEs, and stars.)\n")
}

The standard layout is one column per model, one row per coefficient, with standard errors in parentheses below each coefficient and significance markers (asterisks) attached. Adjusted R-squared, AIC, BIC, and sample size go at the bottom, separated from the coefficients. This is the format virtually every psychology paper uses for nested regression models.

A few additional notes for model tables:

  • Round consistently. Coefficients and SEs are usually reported to 2 or 3 decimals; p-values to 3 decimals (with < .001 instead of zero); R² and adjusted R² to 2 or 3 decimals.
  • Drop the intercept when it is not substantively interesting (which is usually the case for treatment-coded categorical predictors). modelsummary can do this with coef_omit = "Intercept".
  • Rename coefficients to substantively meaningful labels. R’s defaults (e.g., conditionviolent) are programmer-oriented; the reader wants “Condition (violent)” or simply “Condition: violent”.
  • Use a single decimal-point alignment within each column.

34.4 Alternative R tools

gt and modelsummary are the modern defaults. Two other packages are worth knowing about.

The kableExtra package extends the basic knitr::kable() table function with extensive APA-style options. It is slightly more lightweight than gt and produces excellent output for LaTeX and PDF. The API is different but the capabilities are similar.

if (requireNamespace("kableExtra", quietly = TRUE)) {
  library(kableExtra)
  desc_table |>
    kbl(caption = "Descriptive statistics by condition (kableExtra)",
        digits = 2) |>
    kable_styling(bootstrap_options = c("striped", "hover"),
                  full_width = FALSE)
} else {
  desc_table
}

The papaja package is built specifically for producing APA-conformant manuscripts in R Markdown. It includes its own table-building functions (apa_table(), apa_print()) that produce tables formatted exactly to APA specifications, with the manuscript class set up correctly. It is overkill for occasional use but invaluable for researchers writing many APA-style manuscripts.

34.5 The Word (or manual) alternative

Producing tables in R is efficient when you have many tables, when the underlying analysis may change (so the table needs to regenerate), or when you want a fully reproducible workflow. But there is no requirement that your tables be produced by code, and a Word table built by hand can be perfectly correct in APA style.

The principles transfer regardless of the tool:

  • Match APA 7 conventions: title and number above, descriptive note below, minimal lines, consistent decimal precision.
  • Make column headings unambiguous and brief.
  • Right-align numbers; left-align text.
  • Use spanner headings to group related columns rather than repeating “M” and “SD” multiple times.

The advantage of building tables in Word is convenience for one-off documents. The advantage of building them in R is reproducibility and consistency when you have many tables. Many researchers use both: R for the descriptive and model tables that come straight from analysis output, and Word for any tables built from summary data they have collated by hand or from sources external to their own R analysis.

A practical workflow that combines both: use modelsummary or gt to produce HTML or RTF output, copy the output into Word for any final manual tweaking (font, alignment, exact note text), then submit. The “copy from R, polish in Word” pattern is widespread in published research and remains correct under APA 7.
